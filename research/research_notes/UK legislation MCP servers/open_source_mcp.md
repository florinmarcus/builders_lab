# Open-source and community MCP servers for UK law (as of 21 Nov 2026)

Method note: GitHub repo search via `gh search repos` (stars, last push date, licence key as GitHub reports them, run 21 Nov 2026); READMEs read from raw.githubusercontent.com; the official MCP registry API (`registry.modelcontextprotocol.io/v0/servers?search=...`) queried directly; Glama search page fetched; live `tools/list` calls made against five public hosted endpoints on 21 Nov 2026, plus two live test queries. "Last push" = GitHub `pushedAt`, not necessarily last code commit. Smithery search page returned 404 to the fetch tool, so Smithery was only seen through README badges. PulseMCP, mcp.so, mcpservers.org only seen through search results.

## Which UK-legislation MCP servers exist (GitHub, official registry, Glama, Smithery, PulseMCP, mcp.so, mcpservers.org)?

### Takeaway
There are at least 12 UK-legislation MCP servers, and they come in three kinds. (1) Live wrappers of the legislation.gov.uk API with point-in-time reads: The National Archives' own legislation-mcp-ts, cyanheads, Pipeworx, paulieb89 uk-legal-mcp, openlaw-mcp, gb-eli-mcp. (2) Own-index servers: i.AI Lex (hybrid semantic search, government-run but marked experimental), Ansvar (SQLite FTS5, Acts only), and flaviohtavares (title search over a daily Git mirror). (3) Toy or niche ones. Every one that reads legislation.gov.uk covers all UKSIs, so it reaches the Building Regulations 2010, CDM 2015 and the Asbestos Regulations 2012. None covers the Approved Documents, which are gov.uk guidance, not legislation.

1. **legislation-mcp-ts** (The National Archives' `legislation` GitHub org). Repo: https://github.com/legislation/legislation-mcp-ts. 8 stars, last push 2026-11-08. Licence: Open Government Licence v3.0 (README; GitHub shows "other"). TypeScript, self-host only (`npm install && npm run build`; README examples use localhost). I found no public hosted URL in the README. Tools: `search_legislation` (keyword q, title, type, year, subject, department, extent, language, sort), `get_legislation` (text/CLML XML/Akoma Ntoso/HTML, with an "unapplied effects" callout), `get_legislation_metadata` (status, extent, versions, unapplied effects, "supports point-in-time versions"), `get_legislation_fragment`, `get_legislation_table_of_contents`, `search_effects` (amendments/repeals, applied vs unapplied), `get_resource`. Optional tools that only appear when a backend is configured: `search_legislation_advanced` / `count_legislation_advanced` (Research API, needs basic-auth credentials), `search_legislation_semantic` / `search_legislation_sections_semantic` ("experimental", backed by a Lex instance via SEMANTIC_API_BASE_URL), and `search/count/get_powers_and_duties` (TNA powers-and-duties research dataset on Aurora Postgres). Data source: the live legislation.gov.uk API. — [README](https://github.com/legislation/legislation-mcp-ts) (raw: https://raw.githubusercontent.com/legislation/legislation-mcp-ts/main/README.md)

### Inferences
- **Building regulations coverage.** Every live legislation.gov.uk wrapper (items 1, 3–8) can reach uksi/2010/2214 (Building Regulations), uksi/2015/51 (CDM 2015, ID from my memory: verify), uksi/2012/632 (Asbestos 2012, ID from memory: verify), ukpga/2022/30 (Building Safety Act, ID from memory: verify), ukpga/1996/53 (HGCRA 1996) and the Scheme for Construction Contracts SI 1998/649 (ID from memory: verify). That is because these servers pass any type/year/number through to the API. I only confirmed the Building Regulations 2010 live (cyanheads). None of them indexes these instruments specially.
- **Point-in-time.** Real point-in-time reads are offered by legislation-mcp-ts, cyanheads, Pipeworx, paulieb89 and openlaw. Not by Lex (no version parameter seen), Ansvar (roadmap), flaviohtavares, leo-mazzone or gb-eli (not seen).
- **Semantic search.** Only Lex, and legislation-mcp-ts when pointed at a Lex backend. Everything else uses keyword/legislation.gov.uk search or FTS5 BM25.
- **Most mature.** legislation-mcp-ts (official, richest tools, OGL), cyanheads (careful versioning and editorial-status handling, active releases), and paulieb89 (most stars, broadest, hosted). Lex is the only semantic option, but it is self-declared experimental, and one test query surfaced an LLM-OCR'd 1913 local Act first.
- Star counts are tiny across the board (max 21 for a server; 26 for lex-graph). This is a young field of many small projects, with lots of registry-listing churn (Pipeworx and mcpbundles are mass-produced catalogues).
- Hosted endpoints all hit the same legislation.gov.uk API under its fair-use pacing (cyanheads: 1 req/s shared) and its WAF (openlaw, paulieb89). A production user is better off self-hosting, or calling the API from their own server.

### Gaps
- No exact last-commit dates or licences from the GitHub API (blocked in this session). Dates are GitHub `pushedAt` from search.
- Could not query Smithery's search (404). mcp.so, PulseMCP and awesome-mcp-servers lists were not checked directly, so a few small servers may be missing.
- The Lex tool list did not show whether search supports date filters or point-in-time. Lex docs at /docs are a Swagger UI the fetch tool could not render.
- Did not live-test CDM 2015, the Asbestos Regulations or HGCRA on any server.

## Are there MCP servers for gov.uk content in general that would reach Approved Documents?

### Takeaway
Yes, several community servers wrap the keyless GOV.UK Search and Content APIs, and one of them (paulieb89/govuk-mcp) found the Approved Document B pages in a live test. But the Approved Documents themselves are PDFs attached to gov.uk publication pages. These servers return page metadata, HTML sections and attachment links, not parsed PDF text. No official GDS MCP server was found.

- A GOV.UK MCP finds the right Approved Document page and attachment link. To answer from the text, you still need PDF parsing and an index. Our own corpus pipeline (`corpus/`, `system/rag/`) fills exactly that gap.

### Gaps

- No evidence found of an official GDS MCP server.

## Are there construction / building-regulations-specific MCP servers (UK or similar) to compare?

### Takeaway
For England's Building Regulations or Approved Documents there is only one toy (LeoRickayzen/uk-building-code-mcp, a vector search over the merged ADs PDF, "under heavy development"). Abroad, the better comparators are the Canadian Building Code MCP (BYOD PDFs, 24,000+ sections), a Japanese Building Standards Act MCP (e-Gov API), and Legis-Link, a commercial multi-country trades compliance MCP that includes the UK.

## Which are maintained, which are toy projects? Any evidence of quality issues?

### Takeaway
Maintained (pushes in Oct/Nov 2026, releases, registry versions): legislation-mcp-ts, cyanheads, paulieb89 uk-legal-mcp and govuk-mcp, Pipeworx, flaviohtavares, gb-eli-mcp. Stale or toy: Ansvar (last push July 2026, moved to a paid gateway), openlaw (May 2026), LeoRickayzen (Nov 2025), bencium, SamuraiBuddha, Stealth-Labs (self-declared hobby), jurisatlas (templated). The main quality issues are upstream quirks (silent nearest-earlier version, lag in revised text, unapplied effects, WAF blocking, rate limits) and, for Lex, OCR/LLM-digitised old text ranking high.

### Cited Findings
- legislation.gov.uk silently serves the nearest earlier version for a date while echoing the requested date. — [Pipeworx README](https://raw.githubusercontent.com/pipeworx-io/mcp-legislation-uk/main/README.md); seen live in cyanheads ("requested 2020-01-01, applied 2019-01-01")
- Revised text "can lag behind amendments; it is not the authoritative text"; outstanding effects must be checked. — live cyanheads response; [legislation-mcp-ts README](https://raw.githubusercontent.com/legislation/legislation-mcp-ts/main/README.md) (unapplied-effects callout)
- Hosted shared endpoints pace at 1 req/s ([cyanheads](https://raw.githubusercontent.com/cyanheads/uk-legislation-mcp-server/main/README.md)). legislation.gov.uk's AWS WAF blocks generic fetches ([openlaw](https://raw.githubusercontent.com/damankaur-dev/openlaw-mcp/main/README.md)). The hosted uk-legal-mcp can be blocked, so local mode is advised ([paulieb89 README](https://raw.githubusercontent.com/paulieb89/uk-legal-mcp/main/README.md))
- Lex is "experimental … should not be used as a production dependency"; case law is off pending a TNA licence. — [Lex README](https://raw.githubusercontent.com/i-dot-ai/lex/main/README.md)
- flaviohtavares: "unofficial copy … can be out of date or contain conversion errors"; title-only search. — [README](https://raw.githubusercontent.com/flaviohtavares/uk-law-mcp/main/README.md)
- Ansvar: Acts only, no history, DB not redistributed, commercial gateway upsell. — [README](https://raw.githubusercontent.com/Ansvar-Systems/UK-law-mcp/main/README.md)
- Find Case Law is partial: no Crown/County/Magistrates, mostly 2001 onward, no citator. — [Pipeworx uk-caselaw README](https://raw.githubusercontent.com/pipeworx-io/mcp-uk-caselaw/main/README.md)

### Inferences
- For builders_lab, the most reusable pieces are probably (guess, to be validated): legislation-mcp-ts (OGL, official, its cookbook resources) and cyanheads (Apache-2.0, solid version/effects handling) as references for point-in-time legislation fetching. Lex is a possible semantic backend, but it is experimental and runs model-based embeddings on i.AI's side. paulieb89/govuk-mcp shows how to discover AD pages. None replaces a curated, versioned AD + regulations corpus with our own checks.
- Because all of them are third-party remote servers, a user connecting them in Claude adds a separate trust and availability dependency. ADR 0007-style security concerns apply (inference).

### Gaps
- No independent evaluations or benchmarks of any of these servers were found (no HN or Reddit threads surfaced in searches). Quality judgments here come from READMEs plus three live calls.
